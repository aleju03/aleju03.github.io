# src/components/os

Guidance that only applies inside AlejOS, so it loads only when you work here. The layer cake, the routes and the CRT/world loading rules stay in the root `CLAUDE.md`.

## The browser and the shell

**Internet Explorer is a real browser wrapped around one real site.** Nearly everything on the modern web sets `x-frame-options`, so `BrowserApp.tsx` answers for the addresses people actually type: a refusal page with two ways out, its own GitHub and LinkedIn, and the Wayback Machine at whatever year the taskbar clock says. YouTube is the exception that makes the window worth having: the site refuses frames, its *embed* does not, so `browserYouTube.ts`/`YoutubePage.tsx` render their own YouTube over a no-key search proxied by `server/` and hand the player to the real one. The frame attributes are load-bearing there: the generic web iframe's `sandbox` + `no-referrer` turn an embed into *Error 153* rather than a picture. And what plays belongs to the **machine**, not to the page: `pcAudio.ts` takes the walk's distance to the screen glass (fed from `CrtScene`'s `walkTick`, reset when you sit back down) and the component pushes it to the player over `postMessage`, so a song keeps playing from the desk and fades as you cross the room. Same trick, and the same reasoning, as `houseTv.ts` one room over.

**The shell is a fourth kind of thing, next to the store, the apps and the desktop, and it is the reason those three agree with each other.** The desktop and every Explorer window are separate React subtrees where neither is the other's ancestor, so anything that crosses between them is a module store rather than props or context: `dnd.ts` (what the cursor is carrying, plus the hit-test and the drop rules), `clipboard.ts` (cut/copy/paste, where a cut only marks and the move happens on paste) and `dialogs.tsx` (a promise per box, so any plain function can `await confirmBox(...)`). `fs.ts` owns the undo history for the same reason: dragging a file, pasting a copy and pressing Delete are three call sites in two components and one history, so each mutation records its own inverse. Three rules that bite. Drag is **pointer events, not HTML5 DnD** — the native drag image is drawn in untransformed viewport space and lands nowhere near the cursor on the CSS3D tube; the drop target is found by `elementFromPoint` looking for the nearest `[data-drop-path]`, which is why the ghost and any lifted icon must set `pointer-events: none`. **Client pixels are not desktop pixels** on the CRT (the CSS3D transform scales the whole screen DOM), so every coordinate conversion divides by `rect.width / offsetWidth` — a marquee or a ghost that skips it lands somewhere other than under the cursor. And a surface that clears its selection on pointerdown must **exclude `[data-menu]`**, or it tears down its own context menu before the click on it resolves.

## The peeko dashboard

`src/components/os/PeekoApp.tsx` and the five modules under it: the dashboard, an AlejOS app that only appears in the admin's Start menu. Hiding it is presentation; the server refusing the reads is the actual gate. The split is `peeko.ts` (the socket), `peekoFeed.ts` (the **reading layer**: the thing that turns `app_open {app:"vsrg"}` into "opened Rhythm Keys", stitches rows into per-visitor sessions and owns every time format — React-free, so it can be reasoned about on its own), `peekoStyle.ts` (the kind/visitor colour tables and the ticking clock), `peekoUi.tsx` (the parts) and `PeekoPulse`/`PeekoLive`/`PeekoInsights` (the three panels). **Adding a `track()` call to the dashboard is two edits**: a row in `BREAKDOWNS` (`peeko.ts`) and a `case` in `describeEvent` (`peekoFeed.ts`). No server change and no migration, because peeko keeps the props bag unparsed.

**Never render a time from the server.** peeko stamps every feed row with a clock label in the VPS's timezone; reading that on a laptop six hours west is how an evening visit came back saying 6am. Every time in the dashboard is derived in the browser from the epoch `ts` — mostly as an age, which is timezone-free, and where a wall clock is genuinely needed (the chart axis) through `Intl`/`Date` with no zone argument. Ages are measured against the **server's** clock, which rides down with each rollup as `now`, so a skewed local clock cannot shift the five-minute "here now" window.
